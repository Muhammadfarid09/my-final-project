# บันทึกการปฏิบัติงานประจำวัน (Daily Worklog - 2026-10-20)

## ปรับปรุง UI หน้าเข้าสู่ระบบผู้ดูแลระบบเป็นแบบ Modern Split-Screen Card (Admin Login Page Redesign)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ปรับโฉมหน้าเข้าสู่ระบบผู้ดูแลระบบ (`admin/login.php`) จากเดิมที่เป็นกล่องสี่เหลี่ยมเดี่ยวตรงกลาง (Single Box) สู่สถาปัตยกรรมแบบ **Modern Floating Split-Screen Card (แบบ A)** ตามหลักสากลของระบบ Enterprise Dashboard และ SaaS Application
  - โครงสร้างและองค์ประกอบของระบบใหม่:
    1. **การ์ดสปลิตลอยตัว (Floating Split Card):** ออกแบบกรอบขนาด `1040px` พร้อมมุมโค้งมน `24px` และเงาละมุน (Soft Elevation `rgba(15, 23, 42, 0.08)`) บนพื้นหลังสะอาดตา `var(--bg-main, #F8FAFC)`
    2. **ฝั่งซ้าย - อัตลักษณ์แบรนด์ (Brand Hero Side 46%):** ใช้ชุดสี Deep Charcoal & Slate Gradient (`#0B0F17` สู่ `#1E293B`) ประดับด้วยลายเส้นมินิมอลคอร์ทสนามแบดมินตันในมุมมอง Perspective (SVG Background) และสัญลักษณ์ประกายดาวสีทองแบรนด์ (`#FFB91D`) พร้อมหัวข้อ "Hello Admin! 🏸" และข้อความพันธกิจการบริหารจัดการระบบสนามกีฬาแบบครบวงจร
    3. **ฝั่งขวา - ฟอร์มเข้าสู่ระบบ (Form Side 54%):** ใช้พื้นผิวสีขาวบริสุทธิ์ (`#FFFFFF`) แสดงโลโก้ T.S. Pattani พร้อมป้ายกำกับ "Admin Portal", หัวข้อ "Welcome Back!", และช่องกรอกข้อมูลเบอร์โทรศัพท์และรหัสผ่านขนาด 48px ตามเกณฑ์สรีรศาสตร์ (HCI Touch Target)
    4. **ฟังก์ชันสลับการแสดงผลรหัสผ่าน (Show/Hide Password Toggle):** เพิ่มปุ่มดวงตา (`#togglePasswordBtn`) ช่วยให้ผู้ดูแลระบบสามารถตรวจสอบความถูกต้องของรหัสผ่านก่อนส่งข้อมูล ลดความผิดพลาดในการพิมพ์ (Error Prevention)
    5. **ความปลอดภัยและการป้องกัน Double Submission:** คงกลไก `csrf_field()` และระบบตรวจสิทธิ์ Session ไว้อย่างครบถ้วน 100% พร้อมเชื่อมต่อเข้ากับ Centralized Form Submission Interceptor ใน `assets/js/admin.js` อัตโนมัติ
    6. **การแสดงผลบนอุปกรณ์ทุกขนาด (Responsive Web Design):** ปรับเป็นการ์ดแนวตั้ง (Vertical Stack) บนหน้าจอขนาดเล็กกว่า 992px โดยย่อส่วน Hero เป็นแบนเนอร์ด้านบน และคงความสะดวกในการแตะสัมผัสบนมือถืออย่างสมบูรณ์
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: หน้าล็อกอินเดิมของแอดมินใช้รูปแบบกล่องเดี่ยวตรงกลางขนาด 440px ซึ่งขาดการสื่อสารภาพลักษณ์ความน่าเชื่อถือของระบบหลังบ้าน และไม่มีปุ่มสำหรับเปิดดูรหัสผ่าน ทำให้ผู้ดูแลระบบที่พิมพ์รหัสผ่านผิดพลาดไม่ทราบว่าตนเองพิมพ์ตัวอักษรใดผิด
  - วิธีแก้: ออกแบบเลย์เอาต์ใหม่เป็น Split-Screen 2 ฝั่ง เพิ่มโซนสื่อสารภาพลักษณ์และจุดเด่นของระบบ พร้อมติดตั้งปุ่มเปิด/ปิดดูรหัสผ่าน และปรับปรุงการระบุพาธไฟล์สไตล์และสคริปต์ให้ใช้ Dynamic Cache Buster (`filemtime`) ป้องกันปัญหาเบราว์เซอร์จำค่าไฟล์เดิม
* **ไฟล์ที่เกี่ยวข้อง:**

  - docs/2026-10-20_worklog.md

## ปรับปรุงมาตรฐานชื่อไฟล์ข่าวสารและโปรโมชันเป็น news.php พร้อม Backward Compatibility (Promotions to News Standardization)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการยกระดับมาตรฐานชื่อไฟล์แสดงผลข่าวสารและโปรโมชันฝั่งสมาชิก (Frontend) สู่ `news.php` เพื่อให้สอดคล้องกับตารางฐานข้อมูล `News` และระบบจัดการหลังบ้าน `admin/news.php`
  - สร้างไฟล์หลัก `news.php` โดยรวบรวมฟังก์ชันการดึงข้อมูลข่าวสาร กิจกรรม และโปรโมชันแบบ Real-time, ระบบแท็บตัวกรองแยกประเภท, และกล่องป๊อปอัป Modal แสดงรายละเอียดฉบับเต็ม
  - คงความเข้ากันได้ย้อนหลัง 100% (Backward Compatibility) โดยปรับเปลี่ยน `promotions.php` และ `promotion.php` ให้ทำหน้าที่เป็น Forwarder เรียกใช้งาน `news.php` ป้องกันปัญหาลิงก์เสีย (Zero 404 Not Found)
  - ปรับปรุงลิงก์นำทางส่วนกลางให้ชี้ไปยัง `news.php`:
    1. Desktop Navigation Bar ใน `includes/navbar.php` (บรรทัด 62)
    2. Mobile Drawer Navigation ใน `includes/navbar.php` (บรรทัด 240)
    3. Mobile Bottom Navigation Bar ใน `includes/bottom_nav.php` (บรรทัด 28)
    4. Quick Links ส่วนท้ายเว็บไซต์ใน `includes/footer.php` (บรรทัด 39)
  - ปรับปรุงคู่มือการเตรียมสอบ [docs/PROJECT_DEFENSE_HANDBOOK.md](file:///c:/xampp/htdocs/ts-pattani/docs/PROJECT_DEFENSE_HANDBOOK.md) ในตารางแมปปิ้งระดับไฟล์
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: ชื่อไฟล์เดิมฝั่งสมาชิกใช้ `promotions.php` และมีไฟล์ตัวแทน `promotion.php` ทำให้เกิดความไม่สอดคล้องกับชื่อตาราง `News` และชื่อหน้าหลังบ้าน `admin/news.php` ส่งผลให้ผู้ตรวจโปรเจกต์อาจตั้งข้อสงสัยในความไม่เป็นเอกภาพของสถาปัตยกรรมไฟล์
  - วิธีแก้: ยุบรวมการแสดงผลหลักมาไว้ที่ `news.php` ให้ตรงกับชื่อ Entity ของระบบ และคงไฟล์เดิมไว้เป็น Forwarder เพื่อให้บุ๊กมาร์กเดิมหรือผู้ที่พิมพ์ URL ผ่านเบราว์เซอร์ยังคงเข้าใช้งานได้อย่างราบรื่น

## ลบไฟล์ซ้ำซ้อน promotions.php และ promotion.php พร้อมจัดระเบียบตรรกะนำทาง (Remove Redundant Promotion Files & Cleanup)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการลบไฟล์ `promotions.php` และ `promotion.php` ออกจากระบบอย่างเป็นทางการ เพื่อกำจัดความซ้ำซ้อน (Zero Duplication / Clean Architecture)
  - ปรับปรุงและทำความสะอาดอาร์เรย์ตรวจสอบหน้า Active Navigation ใน:

    2. `includes/bottom_nav.php` (บรรทัด 14): ตัดชื่อไฟล์ที่ลบออก เหลือ `$is_promotions_nav = in_array($current_page, ['news.php', 'news_detail.php']);`
  - ปรับปรุงคอมเมนต์ขอบเขตสไตล์ชีตใน `assets/css/promotions.css` ให้เหลือเฉพาะ `news.php`
  - ปรับปรุงตารางแมปปิ้งระดับไฟล์ในคู่มือเตรียมสอบ [docs/PROJECT_DEFENSE_HANDBOOK.md](file:///c:/xampp/htdocs/ts-pattani/docs/PROJECT_DEFENSE_HANDBOOK.md) ให้แสดงเฉพาะ `news.php`
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**

  - วิธีแก้: ตรวจสอบการอ้างอิงทั่วทั้งระบบจนมั่นใจ 100% ว่าไม่มีโค้ดส่วนใดเรียกใช้ไฟล์เก่า แล้วทำการลบไฟล์ตัวแทนทั้งสองออก ทำให้โครงสร้างโฟลเดอร์ฝั่งหน้าบ้านสะอาด ชัดเจน และเป็นไปตามหลัก Single Source of Truth
