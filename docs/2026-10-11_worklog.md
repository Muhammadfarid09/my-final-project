## 1. ระบบความปลอดภัยและการป้องกัน Double Submission (JS Event & Submit Hardening)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  * พัฒนากลไกป้องกันการส่งฟอร์มซ้ำ (Double Submission Prevention) ในฝั่ง Client-side ผ่านตัวแปรแฟล็ก `isSubmitting` / `isBookingSubmitting` ใน [`assets/js/member.js`](file:///c:/xampp/htdocs/ts-pattani/assets/js/member.js)
  * เมื่อผู้ใช้คลิกปุ่มส่งข้อมูล (เช่น ปุ่มเข้าสู่ระบบ, สมัครสมาชิก, ยืนยันการจอง) ระบบจะปิดการใช้งานปุ่มทันที (`disabled = true`), เปลี่ยนเคอร์เซอร์เป็น `cursor: not-allowed`, ลดความโปร่งแสงเป็น `opacity: 0.75`, และแสดงไอคอนสถานะการทำงาน (`<i class="fas fa-spinner fa-spin"></i>`) พร้อมข้อความแจ้งสถานะแบบ Real-time
  * เสริมความปลอดภัยการผูก Event Listener ให้เป็นระเบียบ ไม่ซ้ำซ้อน และทำงานร่วมกับ HTML5 Form Validation อย่างสมบูรณ์

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:* ผู้ใช้งานที่อินเทอร์เน็ตล่าช้ามักกดคลิกปุ่มส่งฟอร์มซ้ำหลายครั้งอย่างรวดเร็ว ส่งผลให้เบราว์เซอร์ส่ง HTTP Request ซ้ำซ้อนไปยัง Backend ก่อให้เกิดปัญหารายการบันทึกซ้ำ หรือข้อผิดพลาดในระดับ Database Transaction
  * *วิธีแก้:* นำเทคนิค State Locking ที่ระดับ JavaScript มาใช้ โดยตั้งเงื่อนไขตรวจสอบสถานะ หากกำลังส่งข้อมูลอยู่จะบล็อกคำสั่งส่งซ้ำทั้งหมด พร้อมให้ Feedback ทางสายตาทันที ทำให้ผู้ใช้รับรู้ว่าระบบกำลังประมวลผล

## 2. สถาปัตยกรรม Single Login Flow & Guest Booking Auth Gate

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  * ออกแบบสถาปัตยกรรมการจองสนามแบบ Progressive Disclosure สำหรับผู้ใช้ทั่วไป (Guest) โดยอนุญาตให้ผู้ใช้ที่ยังไม่ล็อกอินสามารถเข้ามาดูตารางสนาม, เลือกวัน-เวลา, เลือกคอร์ท และเลือกบริการเสริมใน [`booking.php`](file:///c:/xampp/htdocs/ts-pattani/booking.php) ได้อย่างอิสระ
  * ในขั้นตอนที่ 5 (สรุปรายการ) หากระบบตรวจพบว่ายังไม่ล็อกอิน จะแสดง **Guest Auth Gate Card** สีทอง แจ้งเตือนให้เข้าสู่ระบบหรือสมัครสมาชิกก่อนเข้าสู่หน้าชำระเงิน
  * พัฒนาระบบสำรองข้อมูลการจองข้ามหน้าผ่าน Session `$_SESSION['pending_booking']` เมื่อล็อกอินหรือสมัครสมาชิกสำเร็จ ระบบจะพากลับมาที่ `booking.php?redirect=booking.php` พร้อมกู้คืนข้อมูลสนาม วัน เวลา และบริการเสริมทั้งหมดที่ผู้ใช้เลือกไว้โดยอัตโนมัติ

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:* เดิมมี In-Page Modal ล็อกอินซ้อนอยู่ในหน้าจองสนาม ซึ่งเกิดปัญหาความเข้ากันได้ของ Z-index, การขัดแย้งของ Focus, และเมื่อหน้าเว็บรีเฟรช ข้อมูลการจองที่ผู้ใช้เลือกไว้จะสูญหายทั้งหมด ทำให้ผู้ใช้ต้องเริ่มเลือกสนามใหม่ตั้งแต่ต้น
  * *วิธีแก้:* ยกเลิก In-Page Modal แล้วเปลี่ยนมาใช้ Single Login Architecture นำทางไปยังหน้า [`login.php`](file:///c:/xampp/htdocs/ts-pattani/login.php) หรือ [`register.php`](file:///c:/xampp/htdocs/ts-pattani/register.php) ตามปกติ โดยฝากสเตทการจองไว้ใน Session และมีฟังก์ชัน `restorePendingBooking()` ดึงสเตทกลับมาเรนเดอร์ใน JavaScript เมื่อกลับมาถึง

## 9. การแก้ไข CSS Hover และ Selected State ในปฏิทินเลือกวันที่

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  * ลบสีเทาค้างจากสถานะ `:focus` ของเซลล์ปฏิทินออกทั้งหมด
  * ปรับแต่ง `:hover:not(.disabled):not(.selected)` ให้แสดงไฮไลต์สีทองโปร่งแสง `rgba(255, 185, 29, 0.18)` เส้นขอบสีทอง และเงาสีทองตามตำแหน่งเมาส์ทันที
  * บังคับสถานะวันที่เลือกแล้ว (`.selected`, `.selected:hover`, `.selected:focus`) ให้คงพื้นหลังสีทอง `var(--color-gold)` และข้อความสีดำ `var(--text-on-gold)` ถาวร ไม่กลายเป็นสีเทาเมื่อเลื่อนเมาส์มาชี้ซ้ำ
  * กำหนด `transition: all 0.15s ease;` สำหรับการเปลี่ยนสีและเงาอย่างนุ่มนวล

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:* สไตล์เดิมใช้พื้นหลังสีเทาเข้ม (`var(--bg-elevated)`) ในกฎ `:hover` ทำให้เมื่อชี้เมาส์ดูมืดทึบ และเมื่อเลื่อนเมาส์มาชี้ซ้ำบนเซลล์ที่เลือกแล้ว สีเทาก็จะไปโอเวอร์ไรด์สีทองให้หายไป รวมถึงเบราว์เซอร์แสดงกรอบเทาของ `:focus` ค้างไว้
  * *วิธีแก้:* แยกกฎ `:hover` ให้มีผลเฉพาะเซลล์ที่ยังไม่เลือก และล็อกกฎ `.selected:hover` ให้คงสีทองถาวร พร้อมลบ Outline ของ `:focus`

    * แสดงผลเฉพาะสมาชิกที่ผ่านการตรวจสอบสิทธิ์และเข้าสู่ระบบแล้วเท่านั้น (`!empty($_SESSION['member_id']) || !empty($_SESSION['user_id'])`)
    * แสดงผลเฉพาะบนหน้าจอขนาดมือถือ (`@media (max-width: 768px)`) และซ่อนอัตโนมัติบนเดสก์ท็อปและแท็บเล็ต (`display: none;`)

    3. **โปรโมชัน** (`fa-bullhorn`) &rarr; [`promotions.php`](file:///c:/xampp/htdocs/ts-pattani/promotions.php) (รองรับข่าวสารและรายละเอียด)
    4. **ของรางวัล** (`fa-gift`) &rarr; [`rewards.php`](file:///c:/xampp/htdocs/ts-pattani/rewards.php) (รองรับประวัติการแลก)
    5. **โปรไฟล์** (`fa-user`) &rarr; [`profile.php`](file:///c:/xampp/htdocs/ts-pattani/profile.php) (รวมถึงหน้าประวัติการจอง [`booking_history.php`](file:///c:/xampp/htdocs/ts-pattani/booking_history.php))
  * ระบบตรวจจับหน้าปัจจุบันอัจฉริยะ (Smart Active Route Detection) แสดงสถานะ `.active` ด้วยเส้นขีดเรืองแสงด้านบน (Golden Top Border Indicator) พร้อมไอคอนยกตัวและเรืองแสงสีทอง `var(--color-gold)`
  * ดีไซน์ Black & Gold Theme Luxury & Ergonomics:
    * ใช้พื้นหลัง `var(--bg-surface)` พร้อมเส้นขอบทองประกาย และเงายกมิติ `box-shadow`
    * ขนาดความสูง 62px ได้มาตรฐาน Touch Target พื้นที่สัมผัสสบายมือ (Ergonomic Thumb Zone)
    * รองรับขอบจอปลอดภัยของอุปกรณ์รุ่นใหม่ด้วย `env(safe-area-inset-bottom)`
    * ป้องกันการบดบังเนื้อหา (Body Offset) ด้วย `body:has(.mobile-bottom-nav)` เพิ่ม Padding ท้ายหน้า 72px อัตโนมัติ

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:* บนอุปกรณ์สมาร์ตโฟน สมาชิกที่เข้าสู่ระบบต้องเอื้อมนิ้วขึ้นไปแตะ Hamburger Button ที่มุมบนขวาของหน้าจอทุกครั้งที่ต้องการเปลี่ยนหน้า ซึ่งขัดกับหลักสรีรศาสตร์การใช้งานด้วยนิ้วโป้งเดียวบนมือถือ (Thumb Zone Usability), และหากหน้าจอมีความยาว การเลื่อนกลับขึ้นไปด้านบนทำให้เกิด Cognitive & Physical Friction
  * *วิธีแก้:* เพิ่มแถบ Mobile Bottom Navigation Bar ที่ถูกล็อกไว้ด้านล่างจอ (Fixed Dock) ให้ผู้ใช้เข้าถึง 5 ฟังก์ชันหลักได้ทันทีด้วยนิ้วโป้ง พร้อมเขียน CSS เพิ่ม `padding-bottom` บน Body ป้องกันแถบเมนูด้านล่างบดบังปุ่ม CTA หรือ Footer ของทุกหน้า และเชื่อมโยงผ่าน `includes/navbar.php` เพื่อให้ทำงานได้ทันทีโดยไม่ต้องแก้ไขหน้าเพจย่อยทีละหน้า
