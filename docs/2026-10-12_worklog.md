## 2. ปรับปรุงแถบสรุปการจองและแก้ไขปุ่มไปยังหน้าถัดไปบนมือถือ (booking.php)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  * **แก้ไขปัญหาปุ่มถัดไปในขั้นตอนที่ 3 โดนแถบเมนูล่างซ้อนทับ (Mobile Fixed Collision Resolution):**
    * ปรับตำแหน่งการตรึงของ `.sticky-summary-bar` ให้ลอยตัวอยู่เหนือแถบเมนูนำทาง (`.mobile-bottom-nav`) ด้วย `bottom: calc(62px + env(safe-area-inset-bottom, 0px)) !important;` เมื่อผู้ใช้เข้าสู่ระบบ
    * รองรับสถานะผู้ใช้ทั่วไป (Guest) โดยคงตำแหน่งไว้ที่ `bottom: 0;` อย่างถูกต้อง
    * กำหนด `z-index: 999;` ลอยตัวเหนือเนื้อหาหน้าเว็บอย่างสมบูรณ์โดยไม่ทับซ้อนกับ Modal ยืนยันต่างๆ
  * **ออกแบบ Mobile Booking Dock เป็นแบบ 2 ฝั่ง ซ้าย-ขวา (Modern Compact Split Dock):**
    * ปรับเปลี่ยนจากเดิมที่เรียง 3 แถวแนวตั้ง (กินพื้นที่เกือบ 130px) มาเป็นแถวแนวนอน 2 ฝั่ง (ความสูงเพียง ~58px):
      * **ฝั่งซ้าย (Summary Metrics):** แสดงยอดเงินรวม `.sticky-metric-total` ตัวเลขสีทองเด่นชัดขนาด 16px และมีแถวย่อยแสดงจำนวนชั่วโมงกับชื่อสนามขนาดกะทัดรัด 11px
      * **ฝั่งขวา (Primary Action CTA):** วางปุ่ม `.btn-sticky-next` ("ต่อไป: บริการเสริม") เด่นชัดที่มุมขวาล่าง ความสูง 44px ตามมาตรฐาน HCI Touch Target
    * สถานะของปุ่มชัดเจน 100%: แม้ยังไม่ได้เลือกสนาม (`disabled`) ปุ่มก็ยังคงปรากฏชัดเจนพร้อมขอบและข้อความอ่านออก ทำให้ผู้ใช้ทราบทันทีว่าปุ่มถัดไปอยู่ที่ใด และเมื่อคลิกเลือกสนาม ปุ่มจะสว่างเป็นสีทองอร่ามทันที
  * **ปรับระยะเลื่อนในขั้นตอนที่ 3 (`#stepPanel3`):**
    * เพิ่ม `padding-bottom: calc(140px + env(safe-area-inset-bottom, 0px)) !important;` ใน `#stepPanel3` เพื่อให้ผู้ใช้สามารถเลื่อนดูคอร์ทสุดท้าย (คอร์ท 10) และปุ่มเปลี่ยนเวลาเริ่มต้นได้พ้นแนวแถบตรึงด้านล่างทั้งหมด
  * **ปรับโครงสร้างโค้ดตามหลัก DRY และ Separation of Concerns:**
    * จัดกลุ่มสไตล์ของ Booking Wizard ทั้งหมดให้อยู่ใน [`assets/css/booking-wizard.css`](file:///c:/xampp/htdocs/ts-pattani/assets/css/booking-wizard.css) และตัดสไตล์ที่ขัดแย้งออกจาก [`assets/css/responsive-mobile.css`](file:///c:/xampp/htdocs/ts-pattani/assets/css/responsive-mobile.css)

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:* ในหน้าจองสนามขั้นตอนที่ 3 บนมือถือ ผู้ใช้ไม่สามารถมองเห็นหรือกดปุ่ม "ต่อไป: บริการเสริม" ได้ เนื่องจากแถบ `.sticky-summary-bar` และ `.mobile-bottom-nav` ถูกตรึงอยู่ที่ `bottom: 0` ทั้งคู่ และ Bottom Nav มี `z-index: 1000` สูงกว่า จึงทับปุ่มถัดไปที่อยู่ด้านล่างสุดของแถบสรุปจนมิด 100%
  * *วิธีแก้:* ใช้ CSS Selector `body:has(.mobile-bottom-nav) .sticky-summary-bar` เพื่อยกตัวแถบสรุปขึ้น `62px + Safe Area` และเปลี่ยนเลย์เอาต์เป็นแบบ Split Horizontal Dock วางปุ่มถัดไปไว้ฝั่งขวาที่มีขนาดสัมผัส 44px ให้เห็นได้ชัดเจนตลอดเวลา พร้อมเพิ่ม `padding-bottom` ในพาเนลขั้นตอนที่ 3 ป้องกันการบดบังเนื้อหาท้ายหน้า

## 3. ปรับปรุงหน้าระบบชำระเงิน (payment.php) สู่มาตรฐาน Black & Gold Luxury

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  * **ปรับโฉมหน้าระบบชำระเงินตามหลัก HCI และ Black & Gold Theme Luxury:**
    * จัดกลุ่มโครงสร้าง 2 คอลัมน์บน Desktop (`payment-grid-two-cols`) และ 1 คอลัมน์บน Mobile สวยงาม ได้สัดส่วน
    * พัฒนาการ์ดนับถอยหลัง 15 นาทีแบบ Dark Luxury (`.payment-countdown-card`) พร้อมไอคอนนาฬิกาสีทองเรืองแสง และตัวเลขนับถอยหลังสีทองอร่าม `var(--color-gold)` ขนาด 24px
    * ออกแบบการ์ด QR PromptPay ใหม่ (`.payment-qr-frame`) ใช้พื้นหลังสีขาวคมชัดเพื่อให้อุปกรณ์มือถือสแกนจ่ายเงินได้ง่าย พร้อมปุ่มคัดลอกเลขบัญชี/พร้อมเพย์สีทอง และ Tooltip แจ้งเตือน *"คัดลอกแล้ว!"* สีเขียว
    * ปรับการ์ดสรุปรายการจองให้แสดงค่าสนาม, อุปกรณ์เช่า, สินค้า และแสดงยอดสุทธิด้วยตัวเลขสีทองขนาดใหญ่ `24px` พร้อมเงาแสงเรืองรอง
  * **พัฒนาระบบอัปโหลดสลิปตามหลัก Nielsen's Error Prevention:**
    * ออกแบบกล่อง Dropzone (`.slip-upload-box`) ด้วยกรอบประสีทอง `2px dashed rgba(255, 185, 29, 0.4)` รองรับทั้งการคลิกและลากวางรูปภาพ (Drag & Drop)
    * ระบบ Live Image Preview: เมื่อเลือกรูปภาพสลิป จะแสดงภาพตัวอย่างทันที พร้อมระบุชื่อไฟล์และขนาด (KB/MB) และมีปุ่ม *"เปลี่ยนรูปภาพ"* เพื่อให้ผู้ใช้ตรวจสอบความถูกต้องก่อนกดยืนยัน ป้องกันการแนบรูปผิดพลาด
    * Client-side Validation: ตรวจสอบประเภทไฟล์ (JPG, PNG, WEBP) และจำกัดขนาดไม่เกิน 5MB ทันที หากผิดพลาดจะแสดงข้อความเตือนสีแดงโดยไม่ต้องรีเฟรชหน้า
    * ป้องกันการกดส่งซ้ำ (Double Submission Prevention): ปิดการใช้งานปุ่ม (Disabled) และแสดงสถานะกำลังอัปโหลดด้วยสปินเนอร์หมุนทันทีที่กดส่ง
  * **ยกระดับความปลอดภัยระดับธุรกรรม (Transaction Security & IDOR Prevention):**
    * ตรวจสอบความเป็นเจ้าของรายการจอง (`booking_id` + `member_id`) และสถานะ `รอตรวจสอบ` ด้วย Prepared Statement
    * เสริมการตรวจสอบเวลาล็อกสนาม 15 นาที (`booking_lock_expire`) ฝั่งเซิร์ฟเวอร์ หากหมดเวลาจะตัดสิทธิ์และแจ้งเตือนให้ทำรายการใหม่ทันที
    * ป้องกัน CSRF Token ในฟอร์มอัปโหลดสลิป
    * ตรวจสอบความปลอดภัยไฟล์สลิปด้วย `handle_secure_image_upload()` (MIME Type finfo check, Whitelist Extensions, Random Hashed Filename)
  * **แยกสถาปัตยกรรม CSS ตามกฎข้อที่ 2 (Strict Separation of Concerns):**
    * สร้างไฟล์เฉพาะ [`assets/css/payment.css`](file:///c:/xampp/htdocs/ts-pattani/assets/css/payment.css) และลบสไตล์เก่าของ payment ใน [`assets/css/style.css`](file:///c:/xampp/htdocs/ts-pattani/assets/css/style.css) ออกรวม ~180 บรรทัด (Clean Dead Code)

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:* หน้าชำระเงินเดิมยังตกค้างสไตล์สี Light Theme ดั้งเดิมจาก `style.css` เช่น กล่องนับถอยหลังสีเหลืองซีด (`#fff3cd`), กล่อง QR สีเทาอ่อน (`#e9ecef`), และตัวหนังสือสีเทาเข้ม (`#343a40`, `#333`) ซึ่งขัดกับธีมมืดและอ่านยาก, ยอดเงินสุทธิเดิมใช้สีเขียวสดธรรมดาไม่เข้ากับธีมทอง, โค้ดสไตล์ Payment มีความซ้ำซ้อนใน `style.css` ถึง 2 จุด, และขาดการเช็กหมดเวลาล็อก 15 นาทีที่หัวไฟล์ PHP
  * *วิธีแก้:* ย้ายและรวมศูนย์สไตล์ทั้งหมดเข้าสู่ `assets/css/payment.css` โดยเชื่อมโยง Design Tokens Black & Gold, ปรับการ์ดนับถอยหลังและการ์ด QR ให้เป็น Dark Luxury พร้อมกรอบขาวสำหรับสแกน, ปรับยอดเงินสุทธิเป็นสีทองขนาดใหญ่, ลบโค้ดเก่าใน `style.css` ออกทั้งสองจุด, และเพิ่มการเช็ก `$booking['booking_lock_expire'] < time()` ที่หัวไฟล์ PHP เพื่อความปลอดภัย 100%

## 18. แก้ไขปัญหาภาษาไทยเป็นภาษาต่างดาวในไฟล์ Export CSV ทั้งหมด (UTF-8 BOM Injection & Trailing Whitespace Fix)
* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  * **แทรก UTF-8 BOM (Byte Order Mark) ที่ Offset 0 ของสตรีม CSV:**
    * ปรับปรุงสคริปต์ส่งออกข้อมูลส่วนกลาง [`admin/actions/export_csv.php`](file:///c:/xampp/htdocs/ts-pattani/admin/actions/export_csv.php) ซึ่งรองรับการส่งออกไฟล์ CSV ทั้ง 3 ประเภทของระบบ (รายได้ `revenue`, สมาชิก `members`, และการจอง `bookings`)
    * เพิ่มคำสั่งส่ง UTF-8 BOM (`echo "\xEF\xBB\xBF";`) ก่อนการพ่น Header ตารางและแถวข้อมูลแถวแรก เพื่อให้โปรแกรม Microsoft Excel และแอปพลิเคชัน Spreadsheet อื่นๆ สามารถตรวจจับและถอดรหัสอักขระภาษาไทย (Thai UTF-8) ได้อย่างถูกต้องแม่นยำ 100% ไม่กลายเป็นภาษาต่างดาว (Mojibake)
    * เพิ่มกลไกทำความสะอาด Output Buffer (`while (ob_get_level()) { ob_end_clean(); }`) ทันทีหลังการตรวจสอบสิทธิ์ เพื่อล้าง Whitespace หรือข้อมูลตกค้างใน Buffer ออกให้หมดจด มั่นใจได้ว่า BOM อยู่ที่ไบต์แรกสุดของไฟล์อย่างแท้จริง
    * กำหนด HTTP Response Headers ที่สมบูรณ์แบบ: `Content-Type: text/csv; charset=UTF-8`, `Content-Disposition: attachment; filename="..."`, `Pragma: no-cache`, `Expires: 0`
  * **ลบ Trailing Whitespace และแท็กปิด PHP ป้องกัน Header Leak:**
    * แก้ไขโมดูลตรวจสอบสิทธิ์แอดมิน [`admin/includes/auth_check.php`](file:///c:/xampp/htdocs/ts-pattani/admin/includes/auth_check.php) โดยนำแท็กปิด `?>` และช่องว่างท้ายไฟล์ออกทั้งหมดตามมาตรฐาน PSR-12 ป้องกัน PHP พ่นอักขระ Newline/Whitespace ล่วงหน้าก่อนการส่ง HTTP Headers (`Cannot modify header information - headers already sent`)
    * นำแท็กปิด `?>` ท้ายไฟล์ [`admin/actions/export_csv.php`](file:///c:/xampp/htdocs/ts-pattani/admin/actions/export_csv.php) ออกเช่นเดียวกัน เพื่อความสมบูรณ์แบบของไฟล์สคริปต์
  * **การทดสอบความถูกต้องของไบต์ข้อมูล (Binary Hex Verification):**
    * ตรวจสอบด้วยคำสั่ง CLI จำลอง Session ของแอดมินทั้ง 3 ประเภทการส่งออก พบว่าไบต์ที่ 0 ถึง 2 มีค่า Hex ตรงตามมาตรฐานสากลคือ `EF BB BF` (UTF-8 BOM) อย่างถูกต้องสมบูรณ์ ไม่มี Warning หรือ Output อื่นแทรก

* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  * *ปัญหาเดิม:*
    1. เมื่อผู้ดูแลระบบกดดาวน์โหลดรายงาน CSV จากหน้าแดชบอร์ด ไม่ว่าจะเป็นข้อมูลการจอง รายชื่อสมาชิก หรือรายงานรายได้ แล้วนำไปเปิดด้วยโปรแกรม Microsoft Excel ข้อความภาษาไทยทั้งหมดจะแสดงผลเป็นตัวอักษรต่างดาวอ่านไม่รู้เรื่อง เนื่องจากไฟล์ CSV ขาดการระบุ Byte Order Mark (BOM) ทำให้ Excel สันนิษฐานการเข้ารหัสเป็น ANSI / Windows-874 ผิดพลาด
