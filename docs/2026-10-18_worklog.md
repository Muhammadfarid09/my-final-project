## วิเคราะห์ความแตกต่างระหว่าง Conceptual ER-Diagram และ Relational Schema (บทที่ 3)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - จำแนกความแตกต่างเชิงวิชาการระหว่าง Conceptual ER-Diagram (Chen Notation ที่มีกล่องเพชร Relationship) กับ Relational Database Schema / Table Relations (19 ตารางพร้อม PK/FK)
  - ให้คำแนะนำในการจัดโครงสร้างหัวข้อบทที่ 3 เพื่อให้ถูกต้องตามมาตรฐานหลักสูตรสารสนเทศศาสตร์
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: การผสมผสานระหว่างกฎของ Conceptual ERD (ต้องมีกล่องกริยา) เข้ากับ Physical Schema (19 ตารางที่มีเส้น FK แน่นหนา) ทำให้เกิดปัญหาเส้นทับกันและอ่านยาก
  - วิธีแก้: แนะนำให้ใส่ป้ายกริยากำกับบนเส้น Foreign Key หรือแบ่งการนำเสนอในบทที่ 3 ออกเป็น Conceptual ERD (ภาพรวม) และ Relational Schema (โครงสร้างตารางจริง 19 ตาราง)

## ปรับปรุงโครงสร้างผังพิกัดและลำดับ DBML (Twin-Core Layout: Member & Booking)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - วางโครงสร้างแผนผังตารางใหม่โดยใช้หลักการ Twin-Core Layout ปักหมุด Member และ Booking ไว้ตรงกลาง
  - จัดลำดับโค้ด DBML ใหม่เป็น 5 คอลัมน์เพื่อป้องกันเส้น Foreign Key ซ้อนทับกันบน dbdiagram.io
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: โค้ดเดิมทำให้ตารางกระจายตัวแบบสุ่ม เส้น Foreign Key 25 เส้นตัดกันจนอ่านยาก
  - วิธีแก้: จัดกลุ่มตารางตามบทบาท (บริวารสมาชิก -> แกนกลางการจองและการเงิน -> สต็อกสินค้า -> แอดมิน) และกระจายเส้นออกแบบรัศมี
