## พัฒนาระบบบันทึกประวัติการทำงาน (Audit Trail) และระบบแจ้งเตือนสลิปแบบเรียลไทม์ (Live Notification Hub)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ยกระดับระบบสู่มาตรฐานองค์กร (Enterprise Grade) รองรับการนำเสนอต่อพี่เลี้ยงในสถานประกอบการ:
    1. **ระบบ Audit Trail & Activity Log:**
       - เพิ่มตารางฐานข้อมูล `Audit_Log` (ตารางที่ 20) บันทึกข้อมูล `actor_type`, `actor_id`, `actor_name`, `action`, `entity_type`, `entity_id`, `details`, `ip_address`, `user_agent`, `created_at`
       - สร้างฟังก์ชันกลาง `log_activity()` ใน `includes/functions.php` พร้อมกลไก Exception Isolation (ความล้มเหลวของการบันทึก Log จะไม่ขัดขวาง Transaction การเงินหลัก)
       - เชื่อมต่อตัวบันทึกประวัติเข้าสู่ 6 จุดยุทธศาสตร์ของระบบ: ตรวจสอบ/อนุมัติ/ปฏิเสธสลิป (`payment_verify_db.php`), การขายหน้าร้าน (`pos_checkout_db.php`), การพิจารณาคำขอยกเลิกและคืนเงิน (`cancellation_action_db.php`), การแก้ไขแต้มและสถานะสมาชิก (`member_edit_db.php`), การเข้าสู่ระบบ (`login_db.php`) และออกจากระบบ (`logout_db.php`)
       - พัฒนาหน้าจอ `admin/audit_logs.php` แสดงสถิติ KPI สรุปภาพรวม, ตัวกรองตามประเภทกิจกรรม, ผู้กระทำ, คำค้นหา, ช่วงวันที่ พร้อมระบบแบ่งหน้า (Pagination) และหน้าต่างป๊อปอัปดู JSON รายละเอียดเชิงลึก
       - รองรับการส่งออกข้อมูลประวัติระบบเป็นไฟล์ CSV (`actions/export_csv.php?type=audit_logs`)
    2. **ระบบ Live Notification Hub & Real-time Chime Alert:**
       - เพิ่มปุ่มกระดิ่งแจ้งเตือนบนแถบนำทางด้านบน (`top-navbar`) พร้อมตัวเลขนับจำนวนสลิปและคำขอยกเลิกที่รอตรวจสอบแบบ Pulse Badge
       - พัฒนา API `admin/actions/get_notifications.php` สำหรับส่งข้อมูลสถิติและรายการสลิปล่าสุด
       - เพิ่มระบบสังเคราะห์เสียงเตือนสองโทนเสียง (Dual-tone Chime) ด้วย Web Audio API (C5 -> E5) แจ้งเตือนแอดมินทันทีเมื่อมีสลิปโอนเงินใหม่เข้ามา พร้อมสลับเปิด/ปิดเสียงได้
       - ตั้งรอบการตรวจสอบเบื้องหลังทุก 30 วินาทีแบบประหยัดพลังงาน (หยุดทำงานอัตโนมัติเมื่อพับหน้าจอ)
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: เดิมระบบหลังบ้านไม่มีการบันทึกประวัติว่าแอดมินคนใดเป็นผู้กดอนุมัติสลิปหรือแก้ไขข้อมูลสมาชิก ทำให้ขาดความโปร่งใส (Traceability) และแอดมินเคาน์เตอร์ต้องคอยกดรีเฟรชหน้าจอ F5 ตลอดเวลาเพื่อดูว่ามีสลิปใหม่เข้ามาหรือไม่
  - วิธีแก้: พัฒนาระบบ Audit Trail กลางที่บันทึกข้อมูลอัตโนมัติลงฐานข้อมูลในทุกขั้นตอนสำคัญ พร้อมหน้าจอตรวจสอบและส่งออก CSV รวมถึงติดตั้ง Notification Hub บน Navbar ที่ตรวจจับและส่งเสียงเตือนอัตโนมัติเมื่อมีสลิปใหม่เข้ามา ช่วยเพิ่มประสิทธิภาพการทำงานของเจ้าหน้าที่สนามอย่างเห็นได้ชัด

## ปรับปรุงการจัดวางเลย์เอาต์หน้า Audit Logs ให้เป็นระเบียบ สวยงาม และได้มาตรฐาน (Audit Logs UI/UX Reorganization & Alignment)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการปรับปรุงการจัดวางหน้าตาและโครงสร้างส่วนติดต่อผู้ใช้งานใน [`admin/audit_logs.php`](../admin/audit_logs.php) และ [`assets/css/admin.css`](../assets/css/admin.css):
    1. **ปรับปรุงการ์ดสถิติ KPI ภาพรวม (KPI Cards Standardization):** เปลี่ยนมาใช้คลาสมาตรฐานกลางของระบบ (`.dashboard-grid` และ `.stat-card`) เพื่อให้ขนาด ฟอนต์ ไอคอน และสีสันกลมกลืน สอดคล้องกับหน้าแดชบอร์ดหลัก 100%
    2. **จัดตำแหน่งส่วนหัวการ์ดและปุ่มส่งออก CSV (Header Alignment):** นำระบบ `.header-between` มาจัดวาง โดยหัวข้อและคำอธิบายอยู่ชิดซ้าย และปุ่มป้ายส่งออก CSV (`.btn-export`) อยู่ชิดขวาบนบรรทัดเดียวกันอย่างสมดุล แทนที่ลิงก์เดิมที่ตกลงมาอยู่ใต้ข้อความ
    3. **ออกแบบแผงตัวกรองแบบ 2 แถวสมดุล (Structured 2-Tier Filter Panel):**
       - แถวที่ 1 (ค้นหาและหมวดหมู่หลัก): ช่องค้นหาคำสำคัญแบบ Full-width พร้อมไอคอนแว่นขยาย (50%), กล่องเลือกประเภทกิจกรรม (25%), และกล่องเลือกผู้กระทำ (25%)
       - แถวที่ 2 (ช่วงวันที่และปุ่มดำเนินการ): กล่องเลือกตั้งแต่วันที่ ถึงวันที่ อยู่ทางซ้าย และปุ่ม "กรองข้อมูล" กับ "ล้างค่า" จัดวางอยู่ทางขวา แก้ไขปัญหาปุ่มค้นหาเดิมที่ตกไปอยู่โดดเดี่ยวในแถวใหม่
    4. **ป้องกันข้อความในหัวตารางตัดคำผิดเพี้ยน (Table Header No-Wrap Protection):** เพิ่มคุณสมบัติ `white-space: nowrap !important;` ให้กับแท็ก `th` ของ `.admin-table` เพื่อแก้ปัญหาคำว่า *"รายละเอียด (DETAILS)"* ที่ตัดบรรทัดเป็น 3 ท่อน
    5. **สร้างหน้าต่างสถานะว่างเปล่าแบบพรีเมียม (Polished Empty State UI):** เมื่อตัวกรองไม่พบข้อมูล ระบบจะแสดงกล่อง Empty State ที่มีไอคอนวงกลม หัวข้อ คำแนะนำ และปุ่มล้างตัวกรองทั้งหมดอย่างสวยงาม เป็นระเบียบ
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: ในหน้า Audit Logs เดิม ปุ่มส่งออก CSV ตกไปอยู่ใต้ข้อความหัวข้อโดยไม่มีการจัดวางแบบ Flex, แถบตัวกรองเดิมมีความยาวเกินจนปุ่มค้นหาตกไปอยู่โดดเดี่ยวแถวล่างสุด และข้อความหัวตารางคอลัมน์รายละเอียดถูกบีบจนขึ้นบรรทัดใหม่ 3 บรรทัด ส่งผลให้หน้าจอขาดความเป็นระเบียบเรียบร้อย

       - รองรับการจัดระเบียบข้อมูลเป็นตาราง (Embed Fields) กำหนดสีตามประเภทเหตุการณ์ (ทอง: สลิปใหม่, แดง: ขอยกเลิก)
       - มีระบบป้องกันความล้มเหลว (Exception Isolation & Non-blocking Timeout 4s) ทำให้การแจ้งเตือนไม่กระทบต่อความเร็วการทำงานของระบบ

## ยกระดับความปลอดภัยระดับองค์กร: ระบบป้องกันการสุ่มรหัสผ่าน, การตรวจสอบไฟล์อัปโหลดขั้นสูง และหน้าจัดการข้อผิดพลาดพรีเมียม (Production Security Hardening)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการพัฒนายกระดับสถาปัตยกรรมความมั่นคงปลอดภัยตามมาตรฐาน Production Enterprise Security (OWASP Top 10 & CWE Checklist) ครอบคลุม 3 ส่วนหลัก:
    1. **ระบบป้องกันการสุ่มรหัสผ่าน (Login Brute-Force Rate Limiting Engine):**
       - สร้างตารางฐานข้อมูล `Login_Attempts` (ตารางที่ 21) พร้อม Indexing บน `(identifier, user_type, attempted_at)` และ `(ip_address, attempted_at)` เพื่อการประมวลผลที่รวดเร็วระดับมิลลิวินาที
       - พัฒนากลไกควบคุมกลางใน `includes/functions.php`:
         - `check_login_throttle()`: ตรวจสอบความถี่การพยายามเข้าสู่ระบบ จำกัดไม่เกิน 5 ครั้งในรอบ 10 นาที หากเกินกำหนดจะทำการล็อกเอาต์และระงับบัญชี/IP ชั่วคราว 15 นาทีอัตโนมัติ โดยตัดกระบวนการตรวจสอบก่อนถึงขั้นตอน Hash Check ที่กินทรัพยากร CPU
         - `record_login_failure()`: บันทึกประวัติการพยายามล็อกอินล้มเหลวลงใน `Login_Attempts` ควบคู่กับการบันทึกกิจกรรมลง `Audit_Log` เพื่อตรวจสอบย้อนหลัง พร้อมส่งข้อความแจ้งเตือนจำนวนครั้งที่เหลือก่อนถูกระงับ
         - `clear_login_throttle()`: ล้างประวัติการทำรายการผิดพลาดทันทีเมื่อล็อกอินถูกต้อง พร้อมคำสั่ง Housekeeping ล้างข้อมูลเก่าเกิน 24 ชั่วโมงอัตโนมัติ
       - เชื่อมต่อระบบเข้ากับระบบเข้าสู่ระบบฝั่งสมาชิก (`actions/login_db.php`) และฝั่งผู้ดูแลระบบ (`admin/actions/login_db.php`)
    2. **ระบบตรวจสอบและกรองไฟล์อัปโหลดรูปภาพขั้นสูง (Strict Magic Bytes & Anti-Polyglot File Validation):**
       - ยกระดับฟังก์ชันกลาง `handle_secure_image_upload()` ใน `includes/functions.php`:
         - ตรวจสอบโครงสร้างไฟล์และมิติจริงของรูปภาพผ่าน `getimagesize()` (Magic Bytes Header Inspection) ป้องกันการหลอกลวงด้วยการเปลี่ยนนามสกุลไฟล์
         - เพิ่มระบบสแกนเนื้อหาไฟล์ส่วนหัว (Anti-Polyglot & Malicious Web-Shell Inspection) ตรวจจับและระงับไฟล์ที่มีโค้ดแทรกซึม เช่น `<?php`, `<?=`, `<script`, หรือฟังก์ชันคำสั่ง Execute ที่เป็นอันตรายต่อเซิร์ฟเวอร์
    3. **หน้าจอแสดงข้อผิดพลาดระดับลักชัวรีและการตั้งค่าความปลอดภัย Apache (Luxury Error Pages & .htaccess Hardening):**
       - สร้างหน้า Custom Error Pages ที่ออกแบบอย่างประณีตตามอัตลักษณ์ T.S. Badminton (Prestige Gold & Midnight Slate):
         - `404.php`: หน้าแจ้งเตือนกรณีค้นหาหน้าเว็บไม่พบ (Page Not Found)
         - `403.php`: หน้าแจ้งเตือนกรณีถูกปฏิเสธสิทธิ์การเข้าถึง (Forbidden Access)

       - สร้างสไตล์ชีทกลาง `assets/css/error-page.css` ตามหลัก Clean CSS & Separation of Concerns (ปราศจาก Inline Styles และไม่มีการใช้ `!important`)
       - สร้างไฟล์การตั้งค่าเซิร์ฟเวอร์ `.htaccess` ที่รูทของระบบ:

## พัฒนาระบบ Progressive Web App (PWA) ติดตั้งลงหน้าจอโฮมสมาร์ตโฟนเสมือน Native App และระบบ Service Worker Caching

         * มีระบบ Auto-cleanup ลบแคชเวอร์ชันเก่าอัตโนมัติเมื่อมีการอัปเดตเวอร์ชัน
    4. **สร้างแถบเชิญชวนติดตั้งแอปอัจฉริยะ (Custom Install Prompt Banner):**

    5. **ผนวกการทำงานเข้ากับโครงสร้างระบบส่วนกลาง:**
       - สร้างโมดูลกลาง `includes/pwa_meta.php` และผนวกเข้ากับ `includes/navbar.php` (ฝั่งลูกค้า) และ `admin/includes/header.php` (ฝั่งเจ้าหน้าที่) ทำให้ทุกหน้าของระบบรองรับ PWA 100%

## พัฒนาระบบแอนิเมชันตัวเลขวิ่งบนการ์ดสถิติหน้าแรก (Homepage Stats Count-Up Animation)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการพัฒนาระบบ Dynamic Count-Up Animation สำหรับตัวเลขสถิติบนการ์ดหน้าแรก (`index.php`) 4 รายการ (คอร์ทมาตรฐาน BWF, แมตช์ที่จองสำเร็จ, มาตรฐานความพึงพอใจ, และระบบบริการครบวงจร):
    1. **กลไกการคำนวณและขับเคลื่อนแอนิเมชันความเร็ว 60fps:**
       - พัฒนาฟังก์ชัน `initStatsCounterAnimation()` ใน `assets/js/member.js` โดยใช้ `requestAnimationFrame` ร่วมกับ Easing Function แบบ `easeOutQuart` ($1 - (1 - t)^4$) ช่วยให้ตัวเลขวิ่งเร็วในตอนเริ่มต้นและค่อยๆ ชะลอลงอย่างนุ่มนวลก่อนหยุดที่เป้าหมายภายในระยะเวลา 1.6 วินาที
       - มีระบบ Stagger Effect หน่วงเวลาเริ่มต้นของแต่ละช่องสถิติ 80ms สร้างจังหวะการเคลื่อนไหวที่ต่อเนื่องเป็นธรรมชาติ
       - มีระบบตรวจจับ `IntersectionObserver` พร้อม Root Margin เพื่อเริ่มเล่นแอนิเมชันเมื่อผู้ใช้เลื่อนหน้าจอมาถึงการ์ดสถิติ
       - รองรับการเข้าถึงสากล (Accessibility): ตรวจจับ `prefers-reduced-motion: reduce` หากผู้ใช้ตั้งค่าลดการเคลื่อนไหว ระบบจะแสดงตัวเลขจริงทันทีโดยไม่เล่นแอนิเมชัน
    2. **การจัดรูปแบบตัวเลขและการป้องกันการสั่นไหวของเลย์เอาต์ (Layout Stability):**
       - กำหนดคุณสมบัติ CSS `font-variant-numeric: tabular-nums;` บนคลาส `.stat-counter` ใน `assets/css/home.css` เพื่อให้ตัวเลขแต่ละหลักมีความกว้างเท่ากัน ป้องกันปัญหาตัวหนังสือกระตุกหรือขยับไปมาในแนวนอนขณะตัวเลขกำลังหมุนเปลี่ยน
       - จัดรูปแบบตัวเลขสากลด้วย `toLocaleString('en-US')` พร้อมแนบนามสกุลสัญลักษณ์เดิม (`+`, `%`, ` ชม.`) ครบถ้วน
    3. **เอฟเฟกต์ตอบสนองเมื่อนับเสร็จสิ้น (Settle Micro-interaction):**
       - สร้างคลาส `.counter-settled` พร้อมคีย์เฟรมแอนิเมชัน `@keyframes counterPop` ซึ่งจะเด้งขยายเล็กน้อย (Scale 1.08) ด้วยฟังก์ชัน `cubic-bezier(0.175, 0.885, 0.32, 1.275)` เมื่อตัวเลขนับถึงเป้าหมาย ให้ความรู้สึกพรีเมียมและยืนยันผลลัพธ์
    4. **การรักษาความเข้ากันได้และการออกแบบ Progressive Enhancement:**
       - ใน `index.php` ค่าตัวเลขจริงยังคงถูกเรนเดอร์จากฝั่ง Server-side ผ่าน PHP ในแท็ก HTML เสมอ หากผู้ใช้ปิดการใช้งาน JavaScript หรือเครือข่ายโหลดสคริปต์ไม่ทัน ตัวเลขจริงจะยังคงปรากฏอย่างสมบูรณ์ ไร้ปัญหาหน้าจอว่างเปล่า
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: ตัวเลขสถิติเดิมแสดงผลเป็นข้อความนิ่ง (Static text) ขาดความน่าดึงดูดใจ และหากเขียนสคริปต์นับตัวเลขด้วย `setInterval` หรือฟอนต์ปกติ ตัวเลขจะกระตุก ขยับเลื่อนซ้ายขวาทำให้การ์ดเสียสมดุล
  - วิธีแก้: ออกแบบระบบแอนิเมชันด้วย `requestAnimationFrame` ควบคู่กับ CSS `tabular-nums` และ Easing `easeOutQuart` พร้อมตรวจจับการมองเห็นผ่าน `IntersectionObserver` และใส่แอนิเมชัน Pop เล็กน้อยเมื่อสิ้นสุด ส่งผลให้การแสดงผลลื่นไหลระดับ 60fps และคงความสวยงามตามมาตรฐาน HCI

## ติดตั้งระบบแชร์เว็บไซต์ผ่าน Cloudflare Public Tunnel (Instant HTTPS Local Tunnel)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการติดตั้งและตั้งค่าระบบ Cloudflare Quick Tunnel เพื่อเปิดให้บุคคลภายนอก (เพื่อน, อาจารย์ หรือผู้ประเมิน) สามารถเข้าถึงและทดสอบระบบที่รันบน XAMPP ได้ผ่านเครือข่ายอินเทอร์เน็ตสาธารณะ:
    1. **ติดตั้งโปรแกรม Cloudflared Client:** ดาวน์โหลด `cloudflared.exe` เวอร์ชันทางการจาก Cloudflare จัดเก็บไว้ที่ `C:\xampp\cloudflared.exe`
    2. **สร้างสคริปต์เปิดท่อสัญญาณแบบ 1-Click (`start_tunnel.bat`):** อำนวยความสะดวกให้ผู้พัฒนาสามารถดับเบิลคลิกเปิด Tunnel ไปยัง Apache Port 80 ได้ทันที พร้อมคำแนะนำและลิงก์ทดสอบ
    3. **รองรับมาตรฐานความปลอดภัย HTTPS เต็มรูปแบบ:** ทำให้การทดสอบระบบบนอุปกรณ์มือถือจริงสามารถติดตั้ง Progressive Web App (PWA) และลงทะเบียน Service Worker ได้อย่างสมบูรณ์แบบโดยไม่ต้องตั้งค่า SSL Certificate เอง
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: สิทธิ์ GitHub Student Developer Pack หมดอายุ ทำให้ไม่สามารถเปิด Cloud VPS ได้ในขณะนี้ และการส่งไฟล์โปรเจกต์ให้เพื่อนนำไปรันบน XAMPP ในเครื่องเพื่อนเองมีความยุ่งยากและสิ้นเปลืองทรัพยากรเครื่องของเพื่อน
  - วิธีแก้: นำเทคโนโลยี Cloudflare Tunnel เข้ามาเชื่อมต่อ Localhost Port 80 เข้ากับ Cloudflare Edge Network ทำให้ได้ลิงก์ HTTPS สาธารณะทันทีโดยไม่มีค่าใช้จ่าย ไม่ต้องเปิด Forward Port ที่เราเตอร์ และเมื่อเสร็จสิ้นการสาธิตสามารถปิดหน้าต่างเพื่อหยุดการเชื่อมต่อได้ทันที

## จัดระเบียบโครงสร้างไดเรกทอรีและทำความสะอาดหน้า GitHub Repository (Pristine Repository Cleanup)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ดำเนินการจัดระเบียบโครงสร้าง Repository และทำความสะอาดข้อมูลเพื่อเตรียมความพร้อมสำหรับการส่งมอบโครงงานปริญญานิพนธ์และการตรวจประเมินทางวิชาการ:
    1. **จัดระเบียบไฟล์ใน Root Directory ผ่าน `.gitignore`:**
       - เพิ่มกฎ `.gitignore` เพื่อแยกไฟล์การตั้งค่าเฉพาะเครื่อง (`GEMINI.md`) และสคริปต์ยูทิลิตี้สำหรับเดโม (`start_tunnel.bat`) ออกจากการติดตามของ Git (`git rm --cached`) โดยที่ไฟล์ต้นฉบับยังคงอยู่บนเครื่องคอมพิวเตอร์ใน Localhost ตามเดิม 100% ทำให้หน้าแรกของ GitHub มีเฉพาะโครงสร้างโค้ดโปรเจกต์ที่เป็นระเบียบ
       - เพิ่มการป้องกันไฟล์ขยะ เช่น `sess_*`, `*.log`, และ `scratch/`
    2. **ปรับปรุงเครดิตและข้อมูลผู้จัดทำในซอร์สโค้ด (Source Code Sanitization):**

    3. **ปรับปรุงคู่มือโครงการหน้าแรก (`README.md`):**
       - อัปเดตข้อมูลโครงสร้างสคีมาฐานข้อมูลเป็น 22 ตารางสมบูรณ์

       - เพิ่มรายการไดเรกทอรีสำคัญที่พัฒนาขึ้นใหม่ (`database/ts_pattani_db.sql`, PWA `manifest.json`, `sw.js`, และหน้าความปลอดภัย `404.php`)
