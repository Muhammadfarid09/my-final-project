## การวิเคราะห์และปรับปรุงแผนภาพกระแสข้อมูล (DFD Specification)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - ตรวจสอบความถูกต้องของแผนภาพ DFD ในบทที่ 3 เทียบกับระบบจริง 19 ตาราง

## ชี้แจงบทบาทของ D11 (ข้อมูลผู้ดูแลระบบ) ใน Process 1 ของ DFD

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - อธิบายเหตุผลทางวิชาการว่าทำไมต้องคง D11 (ข้อมูลผู้ดูแลระบบ) ไว้ใน Process 1 (จัดการลงทะเบียนและยืนยันตัวตน)
  - ชี้แจงการทำงาน 2 ขาของ Process 1: ขาสมาชิก (สมัคร/ล็อกอิน/กู้รหัสผ่าน D1, D17) และ ขาแอดมิน (ยืนยันตัวตนเข้าสู่ระบบหลังบ้าน D11)
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**

  - วิธีแก้: ยืนยันให้คง D11 ไว้ เพื่อทำหน้าที่ Authentication สำหรับ Admin ป้องกันข้อผิดพลาดตามกฎ DFD

## แก้ไขปัญหา Browser Cache รูปโลโก้หน้าล็อกอินผู้ดูแลระบบ (admin/login.php)

* **ผลการพัฒนา / การแก้ไข (สำหรับนำไปใส่บทที่ 4):**
  - เพิ่ม Dynamic Cache Buster ให้กับแท็ก <img> ของโลโก้ในไฟล์ admin/login.php โดยใช้ฟังก์ชัน filemtime()
  - ทำให้ทุกครั้งที่มีการเปลี่ยนไฟล์ภาพ ts-pattani-generated.jpg เบราว์เซอร์จะดึงภาพใหม่มาแสดงผลทันทีโดยไม่ต้องสั่ง Hard Refresh
* **ปัญหาที่พบและวิธีแก้ (สำหรับนำไปใส่บทที่ 5):**
  - ปัญหา: เมื่อผู้ใช้เปลี่ยนไฟล์ภาพในโฟลเดอร์ assets/img/ แต่หน้าเว็บยังคงแสดงผลเป็นภาพเดิมเนื่องจากเบราว์เซอร์จำค่าแคช (Browser Caching)
  - วิธีแก้: ต่อท้าย URL รูปภาพด้วยพารามิเตอร์ ?v=filemtime(...) เพื่อทำ Cache Busting อัตโนมัติตามเวลาที่มีการแก้ไขไฟล์ล่าสุด
