## 1. ทำอะไรบ้าง (What Was Done)

ปรับปรุงระบบแสดงสถานะและปุ่มการจัดการในหน้า [booking_history.php](file:///c:/xampp/htdocs/ts-pattani/booking_history.php) และ [actions/cancel_booking_db.php](file:///c:/xampp/htdocs/ts-pattani/actions/cancel_booking_db.php) ตามหลักการ **Human-Computer Interaction (HCI)** และหลักความง่ายต่อการใช้งานของ Nielsen (Nielsen's 5th Usability Heuristic: Error Prevention):

### รายการไฟล์ที่สร้างและแก้ไข:
1. **[booking_history.php](file:///c:/xampp/htdocs/ts-pattani/booking_history.php):**
   - **การตรวจจับช่วงเวลา (Time-state Detection):**
     - คำนวณเวลาเริ่มต้น (`$booking_start_ts`) และเวลาสิ้นสุด (`$booking_end_ts`) เทียบกับเวลาปัจจุบัน (`time()`)
   - **การปรับเปลี่ยนสถานะอัตโนมัติตามหลัก HCI:**
     - **รายการในอดีตที่ผ่านพ้นเวลาไปแล้ว (`time() >= booking_end_ts`):** 
       - หากสถานะเดิมคือ "จองแล้ว" จะเปลี่ยนป้ายสถานะเป็น **"ใช้บริการแล้ว"** (สีเทาน้ำเงิน `.status-completed`) และเปลี่ยนปุ่มในคอลัมน์จัดการเป็นข้อความ **"เสร็จสิ้น"** โดยซ่อนปุ่ม "ขอยกเลิก" ทันที เพื่อป้องกันไม่ให้ผู้ใช้กดรายการที่จบไปแล้ว
       - หากสถานะเดิมคือ "รอตรวจสอบ" แต่เลยเวลาจองไปแล้ว จะเปลี่ยนสถานะเป็น **"เลยเวลาจอง"**
     - **รายการที่กำลังอยู่ในช่วงเวลาใช้งาน (`booking_start_ts <= time() < booking_end_ts`):**
       - แสดงป้ายสถานะ **"กำลังใช้งาน"** (สีเขียวสดใส `.status-active`) พร้อมซ่อนปุ่มยกเลิก
     - **รายการในอนาคตที่ยังไม่ถึงเวลา (`time() < booking_start_ts`):**
       - สถานะ "จองแล้ว": แสดงปุ่ม **"ขอยกเลิก"**
       - สถานะ "รอตรวจสอบ": แสดงปุ่ม **"แนบสลิป"** (หากยังไม่แนบ) และปุ่ม **"ยกเลิกการจอง"**
2. **[assets/css/global.css](file:///c:/xampp/htdocs/ts-pattani/assets/css/global.css):**
   - เพิ่ม Class `.status-completed` (สีพื้นหลัง `#f1f5f9`, ขอบ `#cbd5e1`, ตัวอักษร `#475569`) สำหรับป้ายสถานะ "ใช้บริการแล้ว"
   - เพิ่ม Class `.status-active` (สีพื้นหลัง `#ecfdf5`, ขอบ `#a7f3d0`, ตัวอักษร `#047857`) พร้อม Effect Animation Pulse สำหรับ "กำลังใช้งาน"
3. **[actions/cancel_booking_db.php](file:///c:/xampp/htdocs/ts-pattani/actions/cancel_booking_db.php):**
   - เพิ่ม Backend Validation: หากรายการจองได้สิ้นสุดเวลาใช้งานไปแล้ว (`$booking_end_ts <= time()`) จะปฏิเสธคำขอยกเลิก และแจ้งเตือนว่า *"ไม่สามารถยกเลิกได้ เนื่องจากรายการจองนี้ได้ผ่านพ้นเวลาใช้งานไปแล้ว (เสร็จสิ้นการใช้บริการแล้ว)"*

## 2. ระบบเป็นอย่างไร (How the System Works)

### ตารางสถานะและปุ่มควบคุมตามวงจรชีวิตการจอง (HCI State Matrix):

| สถานะใน DB | ช่วงเวลาเทียบกับปัจจุบัน | ป้ายสถานะที่ผู้ใช้เห็น | ปุ่มในคอลัมน์ "จัดการ" | เหตุผลทาง HCI |
|---|:---:|:---:|:---:|---|
| **จองแล้ว** | อนาคต (`time < start`) | 🟩 **จองแล้ว** | 🟦 ดูสลิป + 🟥 **ขอยกเลิก** | ยังไม่ถึงเวลา สามารถส่งคำร้องขอยกเลิกได้ |
| **จองแล้ว** | ปัจจุบัน (`start <= time < end`) | 🟢 **กำลังใช้งาน** | 🟦 ดูสลิป + 🟢 กำลังใช้งาน | กำลังอยู่ในสนาม ไม่สามารถยกเลิกได้ |
| **จองแล้ว** | อดีต (`time >= end`) | 🔘 **ใช้บริการแล้ว** | 🟦 ดูสลิป + 🔘 **เสร็จสิ้น** | **Error Prevention:** จบเกมแล้ว ซ่อนปุ่มยกเลิกเพื่อไม่ให้สับสน |
| **รอตรวจสอบ** | ยังไม่หมดเวลา + ยังไม่จ่าย | 🟨 **รอแนบสลิป** | 🟨 **แนบสลิป** + 🟥 **ยกเลิกการจอง** | ปลดล็อกสนามได้ทันทีหากเปลี่ยนใจ |
| **รอตรวจสอบ** | ยังไม่ถึงเวลา + แนบสลิปแล้ว | 🟨 **รอตรวจสอบสลิป** | 🟦 ดูสลิป + 🟥 **ยกเลิกการจอง** | สมาชิกยกเลิกได้ และส่งเรื่องขอคืนเงินให้แอดมิน |
| **รอตรวจสอบ** | อดีต (`time >= end`) | 🔴 **เลยเวลาจอง** | 🔘 หมดเวลา | เลยกำหนดเวลาใช้งานแล้ว |
| **ยกเลิก** | ทุกช่วงเวลา | ⬜ **ยกเลิกแล้ว** | ⬜ ยกเลิกแล้ว (+ ดูสลิปถ้ามี) | รายการถูกยกเลิกแล้ว ไม่สามารถทำรายการซ้ำ |

## 3. การใช้งานอย่างไร (How to Use / Test)

1. **เปิดหน้าประวัติการจอง:**
   - เข้าไปที่ [http://localhost/ts-pattani/booking_history.php](http://localhost/ts-pattani/booking_history.php)
2. **ผลลัพธ์ที่ปรากฏ:**
   - **รายการที่ผ่านมาแล้วในอดีต (เช่น รายการช่วงบ่ายของวันนี้หรือวันก่อน):**
     - จะแสดงป้ายสถานะเป็น **"ใช้บริการแล้ว"** อย่างชัดเจน
     - คอลัมน์จัดการจะแสดงปุ่ม "ดูสลิป" และป้าย **"เสร็จสิ้น"** โดย**ไม่มีปุ่มขอยกเลิกสีแดง**ปรากฏให้เห็น
   - **รายการที่จองสำหรับวันพรุ่งนี้ หรือเวลาในอนาคต:**
     - จะแสดงสถานะ **"จองแล้ว"** (สีเขียว) และมีปุ่มสีแดง **"ขอยกเลิก"** ให้กดใช้งานได้ตามปกติ
3. **การทดสอบความปลอดภัยฝั่งเซิร์ฟเวอร์:**
   - หากมีการส่งคำขอยกเลิกผ่าน Script หรือ API สำหรับรายการที่ผ่านไปแล้ว ระบบจะปฏิเสธคำขอทันที

## 4. ปัญหาที่เจอหรือแก้อะไรบ้าง (Issues Encountered & Resolved)

* **ปัญหาด้าน HCI และประสบการณ์ผู้ใช้ (UX/HCI Issue):**
  - เดิมทีรายการที่ผ่านเวลาไปแล้ว (เช่น รายการจอง 13:00 น. แต่เวลาปัจจุบันคือ 23:00 น.) ยังคงมีปุ่มสีแดง "ขอยกเลิก" แสดงอยู่ ทำให้ผู้ใช้เข้าใจผิดว่าสามารถกดยกเลิกการจองย้อนหลังได้ และเมื่อกดยกเลิกก็จะเกิด Error หรือเกิดความสับสน ขัดแย้งกับหลัก **Nielsen's 5th Usability Heuristic: Error Prevention**
* **วิธีการแก้ไข (Solution):**
  - นำเวลาสิ้นสุดของการจอง (`booking_end_time`) มาคำนวณแบบ Dynamic Real-time
  - หากรายการผ่านเวลาไปแล้ว ให้เปลี่ยนสถานะเป็น **"ใช้บริการแล้ว"** ทันที พร้อมซ่อนปุ่มขอยกเลิก และแสดงข้อความ **"เสร็จสิ้น"** แทน
  - เสริมการดักจับฝั่งเซิร์ฟเวอร์ใน `actions/cancel_booking_db.php` เพื่อความปลอดภัยสองชั้น
