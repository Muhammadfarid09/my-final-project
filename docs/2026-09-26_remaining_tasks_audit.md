## 1. สิ่งที่ยังไม่ได้ทำ (Pending Features / Completely Missing)

### 1.1 ตารางแสดงความพร้อมของสนามแบบ Real-time (Time-slot Court Availability Matrix)
* **ข้อกำหนด (1.3.2.1):** ผู้ใช้สามารถตรวจสอบความพร้อมใช้งานของแต่ละสนามในแต่ละช่วงเวลาได้แบบเรียลไทม์ ผ่านตารางแสดงผล (Time-Slot Matrix) ก่อนกดจอง
* **สถานะปัจจุบัน:** ในหน้า [booking.php](file:///c:/xampp/htdocs/ts-pattani/booking.php) ยังเป็นเพียง Dropdown เลือกเวลาเริ่มต้น-สิ้นสุด และเลือกสนามทั่วไป โดยไม่มีตารางหรือแถบสีแสดงว่าในวันนั้นๆ ช่วงเวลาใดของแต่ละสนามมีผู้จองไปแล้วหรือไม่ ผู้ใช้จะทราบว่าสนามซ้อนก็ต่อเมื่อกดส่งฟอร์มแล้วโดน Error เด้งกลับมาเท่านั้น

### 1.2 การคำนวณราคาตามช่วงเวลาแบบไดนามิก (Dynamic Peak / Off-Peak Pricing)
* **ข้อกำหนด (1.3.2.2):** ระบบต้องคำนวณราคาค่าบริการสนามแบบไดนามิกตามช่วงเวลา Peak (ช่วงคนเล่นเยอะ เช่น 17:00 - 22:00 น. หรือวันหยุดสุดสัปดาห์) และ Off-Peak (ช่วงกลางวัน/วันธรรมดา)
* **สถานะปัจจุบัน:** ตาราง `Court` ในฐานข้อมูลมีคอลัมน์ `court_peak_price` และ `court_offpeak_price` อยู่แล้ว แต่ในไฟล์ [actions/booking_db.php](file:///c:/xampp/htdocs/ts-pattani/actions/booking_db.php) และ [booking.php](file:///c:/xampp/htdocs/ts-pattani/booking.php) ยังคงใช้การคำนวณราคาแบบอัตราคงที่ (`court_price_per_hour * hours`) โดยยังไม่มี Logic แยกช่วงเวลา

### 1.3 ระบบปรับระดับสมาชิกอัตโนมัติตามเกณฑ์คะแนน (Automated Tier Progression)
* **ข้อกำหนด (1.3.3):** ระบบต้องปรับระดับสมาชิก (Bronze, Silver, Gold) ให้อัตโนมัติตามยอดสะสมคะแนนตลอดชีพ (`point_total_earned`)
* **สถานะปัจจุบัน:** ใน [admin/actions/payment_verify_db.php](file:///c:/xampp/htdocs/ts-pattani/admin/actions/payment_verify_db.php) มีการคำนวณแจกพอยท์และบันทึกประวัติ แต่ยังไม่มี Logic ในการอัปเดตฟิลด์ `member_level` ให้อัตโนมัติ ปัจจุบันยังต้องรอให้แอดมินเข้าไปเลือกเปลี่ยนระดับสมาชิกเองในหน้า [admin/member_edit.php](file:///c:/xampp/htdocs/ts-pattani/admin/member_edit.php)

### 1.4 กราฟและสถิติการใช้งานตามกลุ่มช่วงอายุ (Demographic Age Group Distribution)
* **ข้อกำหนด (1.3.5):** แดชบอร์ดต้องแสดงสถิติผู้ใช้งานตามกลุ่มช่วงอายุ (เช่น ต่ำกว่า 18, 18-25, 26-35, 36-50, 50 ปีขึ้นไป)
* **สถานะปัจจุบัน:** ในแดชบอร์ด [admin/index.php](file:///c:/xampp/htdocs/ts-pattani/admin/index.php) มีเพียงกราฟแสดงสัดส่วนเพศ (Gender) และอาชีพ (Occupation) แต่ยังไม่ได้ดึงฟิลด์ `member_age` มาจัดกลุ่มช่วงอายุเพื่อวาดกราฟ

### 1.5 รายงานสรุปสถิติชั่วโมงยอดนิยม (Peak Usage Hours) และสรุปรายรับ 12 เดือน
* **ข้อกำหนด (1.3.5):** แสดงสถิติชั่วโมงที่มีการจองหนาแน่นที่สุด และสรุปรายได้ภาพรวมรายเดือน (Monthly Revenue)
* **สถานะปัจจุบัน:** ในแดชบอร์ดมีเพียงกราฟแท่งรายรับ 7 วันย้อนหลัง ยังไม่มีการสรุปรายรับรายเดือน 12 เดือน และยังไม่มีการสรุปชั่วโมงยอดนิยม

## 2. สิ่งที่ทำแล้วแต่ยังไม่ครบ / มีข้อจำกัดหรือติดปัญหา (Partially Done & Minor Issues)

### 2.1 ระบบแชทฝั่งสมาชิกยังไม่มี Real-time AJAX Polling
* **สิ่งที่ทำแล้ว:** สมาชิกและแอดมินสามารถส่งข้อความสนทนากันได้ มีการแยกผู้ส่งชัดเจน บันทึกลงฐานข้อมูล `Chat` เรียบร้อย
* **จุดที่ยังไม่ครบ:** หน้า [chat.php](file:///c:/xampp/htdocs/ts-pattani/chat.php) ของสมาชิกยังเป็นการส่งฟอร์มแบบดั้งเดิม (Page Reload) และไม่มีคำสั่ง JavaScript Polling (ดึงข้อความอัตโนมัติทุกๆ 3-5 วินาที) ทำให้เมื่อแอดมินตอบแชทกลับมา สมาชิกจะไม่เห็นข้อความใหม่จนกว่าจะกดรีเฟรชหน้าจอเอง

### 2.2 การคืนสต็อกอุปกรณ์เมื่อแอดมิน "ปฏิเสธสลิป" (Reject Slip Stock Restoration)
* **สิ่งที่ทำแล้ว:** แอดมินสามารถตรวจสอบสลิปและเลือก "ยืนยัน" หรือ "ปฏิเสธ" ได้
* **จุดที่ติดปัญหา:** ในไฟล์ [admin/actions/payment_verify_db.php](file:///c:/xampp/htdocs/ts-pattani/admin/actions/payment_verify_db.php) เมื่อแอดมินกด "ปฏิเสธ" ระบบเปลี่ยนสถานะการจองเป็น 'ยกเลิก' แต่ยังไม่ได้บวกสต็อกสินค้า/อุปกรณ์เช่าที่ถูกตัดไปตอนจองกลับคืนเข้าสู่ตาราง `Product` (มีคอมเมนต์ TODO ค้างอยู่ในโค้ด)

### 2.3 สถานะ 'ยกเลิก' ใน ENUM ของตาราง Rental
* **สิ่งที่ทำแล้ว:** [admin/includes/auto_cancel.php](file:///c:/xampp/htdocs/ts-pattani/admin/includes/auto_cancel.php) มีระบบยกเลิกบิลที่หมดเวลา 15 นาทีอัตโนมัติ
* **จุดที่ติดปัญหา:** คำสั่งใน `auto_cancel.php` พยายามสั่ง `UPDATE Rental SET rental_status = 'ยกเลิก'` แต่ใน ENUM ปัจจุบันของ `Rental` มีเพียง `'รอตรวจสอบ'`, `'กำลังเช่า'`, `'คืนแล้ว'`, `'ชำรุด'`, `'สูญหาย'` (ยังไม่มีค่า `'ยกเลิก'`) อาจทำให้เกิด Warning หรือไม่เปลี่ยนสถานะในโหมด Strict

### 2.4 การแสดงประวัติการทำรายการพอยท์ฝั่งสมาชิก (Point History UI)
* **สิ่งที่ทำแล้ว:** ฐานข้อมูลมีตาราง `Point_Transaction` คอยเก็บประวัติการได้รับพอยท์และการใช้พอยท์แลกรางวัลอย่างสมบูรณ์
* **จุดที่ยังไม่ครบ:** ยังไม่มีหน้า UI แสดงประวัติการเคลื่อนไหวของพอยท์ (เช่น ในหน้าโปรไฟล์ หรือหน้ารางวัล) ให้สมาชิกสามารถตรวจสอบรายการย้อนหลังได้ว่าได้แต้มจากบิลใด หรือใช้แลกอะไรไป
